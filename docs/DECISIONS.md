# Decisions

| Date | Decision | Why |
| --- | --- | --- |
| 2026-11-08 | Sell first to DPO consultancies, not single organisations | One sale brings many client organisations; per-client pricing fits their retainers |
| 2026-11-08 | Deadline rules follow ICO guidance, tested against its worked examples | A wrong date is the product's worst failure |
| 2026-11-08 | AI never acts alone: a person confirms triage and sends letters | Keeps responsibility with the controller; limits harm from a misread |
| 2026-11-08 | Postgres with row-level security as the isolation boundary | Isolation must not depend on app code being perfect |
| 2026-11-08 | Next.js + Supabase + shadcn/ui | Largest ecosystem, best AI tooling support, hosted Postgres with auth and RLS in one service |
| 2026-11-08 | The Data API grants reach the signed-in role only; the anonymous role gets nothing in `pd` | The public form (slice 5) will write through a server route, so nothing needs anonymous table access; Supabase's standard grants would open every table to it |
| 2026-11-08 | Next.js Cache Components switched off for now | Every page is per-user, so there is nothing to prerender yet, and with it on each session read needs its own Suspense boundary. Revisit when a public page is worth caching |
| 2026-11-08 | A new user creates their consultancy through `pd.create_partner`, a definer-rights function, and becomes its admin | `partners` has no insert policy and a membership can only be added by an existing admin, so nothing else could bootstrap the first user |
| 2026-11-08 | Partner admins must enrol an authenticator app; the app sends them to enrol or to enter a code before the desk | Admins can read every client's data. Enforcement in the database itself (an `aal2` check in the policies) joins the slice 7 checklist |
| 2026-11-08 | Every case action is one database function call (`pd.record_case_action`) that changes the case and writes its audit event in the same transaction | Two statements from the app could leave a change without its event. The function also refuses impossible actions, so the rules live in one place |
| 2026-11-08 | Case references are `<client code>-<number>`, numbered per client and never reused | Short enough to quote on the phone; the client code makes the owner obvious in a mixed list |
| 2026-11-08 | Action dates may not be in the future | A deadline worked out from a future date would be fiction; backdating is allowed because requests are often logged late |
| 2026-11-08 | Inbound email is keyed by a per-client token in the forwarding address, through definer-rights functions the anonymous role may call | The app then needs no service key anywhere. The anonymous role has usage on the `pd` schema so those functions resolve, but no table grants |
| 2026-11-08 | Triage uses Claude Opus 5.5 at low effort with a fixed JSON schema; the keyword check runs when a client has AI off, no key is set, or the call fails | The screen always says which one spoke. A person confirms every result and the audit event records both |
| 2026-11-08 | Letter drafts are copied, never sent | The app never sends email on its own (CLAUDE.md). The person sends from their own mailbox |
| 2026-11-08 | Client codes are unique across every consultancy, not just within one | The public form lives at `/r/<code>`, so a code has to name one client. Case references were already unique across the whole table, so this only made an existing assumption explicit |
| 2026-11-08 | The public form writes through definer-rights functions keyed by the client code and a hashed one-time token; the submissions table has no grants for any app role | Nothing a visitor can reach needs a session or a table grant, and a copy of the table cannot be used to verify someone else's request |
| 2026-11-08 | A web form request is received on the day the link is opened, not the day the form was filled in | The design standard: the clock starts when the request is complete, and an unverified address is not a complete request. Unverified submissions are deleted a week after the link expires |
| 2026-11-08 | The app sends two transactional emails for the public form (the link and the confirmation), through Resend | These are messages the requester asked for by filling in the form. "The app never sends email on its own" in CLAUDE.md means case correspondence: letters are still drafted, copied and sent by a person |
| 2026-11-08 | The confirmation states a legal response date based on the requester's own choice of type, before a person has triaged it | A requester expects to be told when to expect an answer (design standard §6). The sentence says the time runs later if identity has to be checked, and the consultancy confirms the date in its own acknowledgement. Revisit if pilots find the date causes disputes |
| 2026-11-08 | Web form requests get their own reference (`<code>-W0001`) that the case keeps as `source_ref` | Cases are numbered only when a person accepts the item, so the requester cannot be given the case reference on the spot. The case page and search both know the web reference |
| 2026-11-08 | The service role is used in one place only: the nightly job route, server-side, behind `JOBS_SECRET`, with explicit grants for just what the job does | Reminders have to see every consultancy's cases and read members' email addresses, which no user session can. Nothing else in the app has that key, and the browser never does |
| 2026-11-08 | Reminder digests are internal email to the consultancy's own staff, one per person per night | They are not case correspondence, so they sit outside the "never sends letters" rule, like the public form's emails. The digest says nothing has been sent to the requester |
| 2026-11-08 | The monthly report PDF is rendered on the server with @react-pdf/renderer, from the same text as the page | No browser needed on the server; one page, the client's name and colour, same words as the page so the two never disagree |
| 2026-11-08 | Bank holidays for all three regions come from the GOV.UK feed, upserted nightly | One source for the dates, and Scotland and Northern Ireland work without hand-typed lists. The engine's built-in England and Wales list is only a fallback |
| 2026-11-08 | A partner admin's membership counts in the policies only when the token says `aal2` | The app already sent admins to enrol, but a rule only the app enforces can be skipped by calling the API directly. Now the database refuses them. Other roles see one client at most and are not yet required to enrol |
| 2026-11-08 | Idle sessions end after 8 hours (`SESSION_IDLE_HOURS`), enforced by the proxy with an HTTP-only cookie | Supabase's own inactivity timeout is a Pro feature; this works on every plan and sends the person to sign-in with a sentence saying why |
| 2026-11-08 | The public form caps each sender address at ten submissions an hour, storing only a daily-salted hash of the address | Enough to stop a script filling the inbox without storing network addresses, which would themselves be personal data |
| 2026-11-08 | Legal pages are drafts written by the developer, shown with a banner until a solicitor has reviewed them | Better to have the structure and the facts (sub-processors, retention, roles) written down and visible than nothing; the banner stops anyone mistaking them for terms in force |
| 2026-11-08 | `AI_DISABLED=1` switches AI off for the whole deployment | A provider's terms or an incident can change overnight; one environment variable is faster than editing every client |

## Open questions

- Working name "Privacy Desk": check Companies House and the UK IPO trade mark register before branding.
- Reminder recipients: every member who can see the case gets the digest, with no per-person switch. Add one in settings once someone asks for it.
- Second factor for client users and read-only users: today only partner admins must enrol. Decide before the first client organisation gets its own sign-in.
- Content security policy: inline scripts and styles are allowed because Next emits them. Move to a nonce-based policy once the app is deployed and the exact script set is known.
- The case page's "no bank holidays loaded for Scotland yet" notice disappears once the nightly job has run. Until the job is scheduled, run it by hand after creating the project (see `apps/web/README.md`).
- Should complaint outcomes have an internal target per client (default 28 days) or a fixed one? Ask the first pilots.
- Inbound email domain: forwarding addresses need a domain whose MX records point at Postmark (or Resend inbound). Which domain, and who owns the Postmark account? Until then the client page shows the address without a domain.
- AI provider terms: requester messages go to Anthropic for triage and drafting. The slice 7 checklist needs the data processing agreement and no-training terms confirmed before any real data; the per-client switch already exists.
- Display names: the audit trail can only say "you" or a shortened user id, because nothing stores a person's name. A small profiles table (user id, name) filled at first sign-in would fix it. Which slice?
- Inviting colleagues: the first user is the consultancy's only member. Adding a second admin or a client user needs an invitation flow (email, accept, membership row). Which slice, and should client users sign in at all in the first version?
- Supabase's built-in email sender allows only a few messages an hour, which limits sign-in testing. The app now has a Resend sender for the public form (slice 5); point Supabase Auth's SMTP settings at the same Resend account before pilots so sign-in links go the same way.
- Rate limits on the public form: today there is a honeypot field, a 24-hour token and a cap of five submissions an hour per email address and client. Per-IP limits and a bot check belong to the slice 7 checklist.
- Default privileges from migration 0002 hand every new table to the signed-in role. Migration 0006 revokes them for `form_submissions`; any future table that no app role should read needs the same line. Consider dropping the default privileges and granting per table instead.
- Two copies of the deadline rules now exist: `packages/clocks/clocks.js` (JS, 14 tests) and `apps/web/src/lib/clocks.ts` (TypeScript, same tests plus typing). CLAUDE.md names the package as the single source of truth. Proposal: once slice 3 ships, make the TypeScript module the source and either retire `packages/clocks/` or turn it into a workspace package the app imports. Until then, change both and run both test suites.
